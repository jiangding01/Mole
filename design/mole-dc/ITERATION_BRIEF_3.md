# Mole for Mac 设计稿迭代需求 · 第三轮（致 Claude Design）

> 2026-08-15 · 前两轮已全部实现并真机走查（含一次布局风暴修复，见实现侧提示）。
> 本轮主题：**确认页条目的可读性与行级状态**。素材来源：真机使用反馈 + 对官方 Mole Mac 确认页的参考走查（借鉴其信息组织，不迁移其视觉语言）。
> 第一轮 P4 四项继续后置。

---

## P1 · 0B 长尾折叠（r2 分隔线的升级）

r2 的"分隔而不聚合"落地后真机验证：177 条 0B 行即使沉底+置灰，翻页翻到时仍是噪音主体。用户明确反馈"很多 0B 是不是可以不展示"。

**约束（信任承诺①）**：apply 会删除这些空目录，**完全隐藏不可接受**——用户必须能看见将被删除的每一项。

**需求**：把 r2 的 0B 分隔线升级为 **disclosure**：默认收起（"以下 177 项为 0 B · 空目录或已被系统清空 [展开查看]"），点开逐条显示（沿用 62% 透明与 hover 说明）。勾选语义不变（收起时仍默认勾选、计入项数）。请定稿收起/展开的视觉与"收起状态下如何暗示已勾选"。

## P2 · 条目友好名 + 路径副行

现状：条目只显示裸路径，`~/Library/Application Support/Google/Chrome/…5289352a/109090c8-…` 这类行不可读。官方版的"Xcode 模块缓存 + mono 路径副行"双行形态可读性显著更好。

**需求**：条目行升级为**语义名主行 + mono 路径副行**。语义名来源是 GUI 侧"知名路径 → 名称"映射表（Xcode DerivedData、npm cache、浏览器 profile 等常见几十类），**映射不到的回退为纯路径单行**（现状形态，绝不编造名称）。请定稿双行行高、副行截断规则、以及回退单行与双行混排时的对齐。注意行高变化与 P1/分页的组合空间成本。

## P3 · 行内动作：Finder 显示 + 加入白名单

官方版每行的文件夹/盾牌双动作是复核刚需。我们的数据能力：`robot whitelist add --mode clean` 现成。

**需求**：
1. 行 hover 显露两个动作图标：**在 Finder 中显示**、**加入白名单（盾牌）**；
2. 加白名单的结果状态机请定稿：该项从清单中立即移除？还是灰置+"已加白名单"徽标（可撤销）？（倾向后者——可撤销、可见后果）；
3. 白名单动作要有一句后果说明（它影响 CLI 与 GUI 的所有后续扫描）。

## P4 · 行级"应用打开中 / 系统占用"锁定态

官方版对运行中应用的缓存子项做**行级锁定**（锁图标替代复选框 + 琥珀"应用打开中"徽标），比我们 r2 的页顶守卫条粒度细。我们协议里 `item.blocked_by` 字段**已预留未用**——CLI 侧补充按项上报后即可点亮。

**需求**：
1. 锁定行形态：锁图标替代复选框、徽标（应用打开中 / 系统占用）、不可勾选、不计入已选统计；
2. 与 r2 页顶守卫条的关系定稿：守卫条 = 段级"整段没扫"（无字节数），行级锁 = "扫到了但此刻不可删"（有字节数）——两者并存的信息分工与文案区分；
3. 锁定行的 hover 说明（"退出 <应用> 后重新扫描可清理"类措辞）。

## P5 · 同质子项聚合行（需要裁决的红线边界）

官方版把同一容器下的同类子项聚合为父行（"com.tencent.QQMusicMac 缓存 · 3 项 · 28.1 MB"），展开后逐项可勾。r2 的"不聚合"红线针对的是**跨语义聚合**（把 45 条不同东西并成一条"用户缓存"）；同父目录同容器的子项聚合是否违背"删之前看得见"，请设计裁决：

- 若采纳：限定条件（仅同容器/同父目录、父行必须显示子项数+总量、展开后逐项复核与勾选）、默认展开还是收起；
- 若拒绝：说明理由入 CHANGELOG，我们停止考虑此形态。

## P6 · "推荐"选择预设

官方版底部"全选 · 清空 · 推荐"三连。我们的 `default_selected`（safe 勾 / caution 不勾）语义上就是"推荐集"。

**需求**：确认条上加第三个快捷动作"推荐"（= 回到协议默认勾选集），与全选/清空并列。命名与位置请定稿（也可叫"默认"）。

## 明确不做（防走样）

- 永久清理默认（废纸篓默认是我们的安全差异化，不动）；
- 官方版的视觉语言迁移（地球动画等）；
- 字节数承诺红线继续适用（P4 锁定行有字节数是因为**扫到了**，与守卫条的"没扫"本质不同）；
- 第一轮 P4 四项继续后置。
