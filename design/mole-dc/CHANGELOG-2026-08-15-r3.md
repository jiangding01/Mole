# Mole for Mac 设计稿 · 第三轮变更（r3）

2026-08-15 · 唯一变更文件：`Mole.dc.html`（确认页条目层）。设计语言不变（配色 / 圆角 / 字号阶 / 徽标体系沿用 r1–r2）。

---

## P1 · 0B 长尾：从数据源头移除

- `ZERO_IN_GUI = false`（`Component` 类常量）：`buildQuick()` 不再生成 0B 目标，GUI 清单从 1854 项降到 **1624 项**（各组条目数相应下降；如 应用与工具 761 → 756、开发者工具 349 → 172）。
- r2 的 **0B 分隔线 / 62% 置灰 / 「全 0B 组」变体卡** 代码全部保留，但只在 `ZERO_IN_GUI = true` 时出现——**降级为兜底态**，正常扫描路径不会触发。`it.isZero / it.zeroHead / g.allZero` 三条分支未删，CLI 侧若某天回传 0B 项仍能正确渲染。
- r2 的「0B 折叠 disclosure」需求作废，未实现。

## P2 · 语义名主行 + mono 路径副行

- 条目行改为双行：**主行**语义名 12.5px / 500 / `--text`；**副行**路径 10.5px mono / `--text-mute`，行高 1.42。
- **回退单行**：映射不到知名路径的目标（约 18% 的长尾）不显示任何名称，只渲染路径一行，字号提到 **12px、色阶提到 `--text-dim`**（它此时是主信息）。绝不编造名称。
- **对齐定稿**：双行与单行回退共用 `min-height: 42px` 的居中行盒，复选框 / 徽标 / 体积列 / 行内动作全部 `align-items:center`，因此两种形态混排时左右两端仍成列，只有中间文本块的行数不同。
- **副行截断规则**：`direction:rtl; unicode-bidi:plaintext` + 省略号——**从头部截断、保留尾段**（`…/109090c8-…` 这一段才是识别用的），完整路径挂在 `title` 上。
- **空间成本**：行高 28pt → 42px（+50%）。分页仍是每组首屏 12 项 + 「再显示 50 项」，未放大，避免抵消 r2 的性能修复。**未引入任何常驻动画**（锁定行是静态琥珀徽标，无呼吸效果），26ms 预算不受新增帧成本影响。

## P3 · 行内动作：Finder 显示 + 加入白名单

- 每行右端两个动作图标：**在 Finder 中显示**（文件夹）、**加入白名单**（盾牌）。常驻但 `opacity .45`，hover 升到 1 并加底色——纯 CSS，不依赖 JS hover 探测（避免又一次数百行的事件/测量开销）。
- **状态机定稿（采纳可撤销方案）**：加白名单 **不从清单移除**，改为 `opacity .5` + 蓝灰「已加白名单」徽标 + 取消勾选 + 不再计入已选统计；再点盾牌即撤销，重新可勾。理由：删除式移除让用户失去「我刚做了什么」的现场，撤销成本高。
- **后果说明**：盾牌 `title` 为「加入白名单 · CLI 与 GUI 的所有后续扫描都会跳过此路径」；已加白后变为「从白名单移除 · 后续扫描将重新纳入此路径」。对应 `robot whitelist add --mode clean`。
- 聚合父行的盾牌 = 对全部子行批量加白。

## P4 · 行级锁定态（`item.blocked_by`）

- 锁定行：**锁图标替代复选框**（琥珀 `#E3B34E`）+ 行尾琥珀徽标「应用打开中」/「系统占用」+ 不可勾选（`selectable()` 直接排除）+ 不计入已选字节与已选计数；**体积照常显示**（扫到了）。行透明度 .72，与白名单的 .5、受保护的 .55 区分。
- **与页顶守卫条的分工定稿**：
  - 守卫条 = **段级「整段没扫」**，无字节数。文案改为「N 个分组因应用运行中**整段未扫描**」，展开脚注新增一句：「清单里标『应用打开中』的单行是另一回事：那些已经扫到体积，只是此刻不可删。」
  - 行级锁 = **「扫到了但此刻不可删」**，有字节数。
- **hover 说明**（锁图标与徽标同一 `title`）：「已扫到体积，但 Google Chrome 正在运行 · 退出后重新扫描即可清理」；系统占用为「已扫到体积，但系统此刻正在占用 · 暂不可删除」。
- **父子继承**：`blocked_by` 在聚合父行上时，全部子行继承 `blk`，父行与子行各自渲染锁图标与自己的徽标、各自保留体积。

## P5 · 同质子项聚合行 —— **采纳**（限定条件）

裁决：r2 的「不聚合」红线针对**跨语义聚合**（把 45 条不同东西并成「用户缓存」一条）。同容器同类子项的聚合不违背「删之前看得见」，因为**每个子项仍然逐条列出、逐条可勾、各自有体积**，父行只是一个可折叠的表头。

限定条件（写死在实现里）：
1. 仅限**同一容器 / 同一父目录**下的子项（`~/Library/Containers/com.x/Data/Library/Caches/*`）；跨目录、跨语义一律不聚合。
2. 父行必须同时显示 **子项数 + 总量**（`Arc 缓存 · 3 项 · 20 MB`）。
3. **默认收起**（1600+ 行的清单里默认展开会重新变成长尾噪音），一次点击展开；展开后子行**一级缩进 22px**、各自体积、各自行内动作。
4. 父行勾选 = 全子联动，三态（全选 / 半选横杠 / 未选）；父行本身不参与体积统计（`size = 0`，总量由子行汇总），杜绝重复计数。
5. 父子锁定继承见 P4。

## P6 · 「推荐」选择预设

- 确认条右侧新增 **全选 · 清空 · 推荐** 三连（放在「重新扫描 / 清理已选项」左侧，与主操作同一行、弱化为文本按钮）。
- 「推荐」= 协议 `default_selected`：`safe` 勾、`caution` 不勾；当前选择恰好等于推荐集时，「推荐」字色高亮为 `--accent`，作为一个无声的状态指示。
- 命名定稿为「推荐」而非「默认」：用户读到的是一个建议，不是一个出厂设置。

## i18n

- 新增 TR 词条 1 条：守卫条展开脚注（含行级锁区分句）。
- 本轮其余新文案全部为 **运行时双语字面量**（`_lang==='en'? … : …`），不进 TR 表，与 r2 同一处理方式：行级锁徽标与 hover 说明、白名单徽标与两态 `title`、Finder 动作 `title`、聚合父行 `N 项 · 体积`、全选 / 清空 / 推荐。理由：这些串含变量（应用名、子项数、体积）或成对状态，走 TR 表会退化成拼接。
- 聚合子行与长尾条目沿用既有的 `it.en` 英文名字段，映射不到名称的回退行本身没有可译文本（纯路径）。

## 实现侧提示

1. `ZERO_IN_GUI`、`RUNNING`、`hex()`、`buildQuick()` 的聚合与长尾生成逻辑都是**设计稿造数用的**，生产实现从 CLI 协议取数，可整体删除。
2. 行级锁定读 `item.blocked_by`：设计稿用 `'app:<应用名>'` / `'sys'` 两种前缀模拟，真实协议只要能区分「运行中应用（带应用名）」与「系统占用」即可。
3. 白名单为**本地会话内状态**（`it._wl`），未做持久化；真实实现落到 `robot whitelist add --mode clean` 并需要在下次扫描前生效。
4. 42px 行高 + 首屏 12 项的组合已按 26ms 预算取舍；若实现侧改为虚拟列表，聚合父行展开会插入 3–4 行，注意高度估算不能按定高算。
